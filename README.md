# Hedgelion D&D Master

Среда AI Dungeon Master для длительных D&D-кампаний в ChatGPT Projects с GitHub как долговременным хранилищем канона.

Главная цель проекта — чтобы размер рабочего контекста зависел от сложности текущей сцены, а не от количества сыгранных сессий. Игровые факты никогда не сохраняются в ChatGPT Memory.

## Установка

1. Создайте отдельный ChatGPT Project.
2. Скопируйте содержимое `INSTALL/PROJECT_INSTRUCTIONS.txt` в Project Instructions.
3. Добавьте `00_DND_BOOTSTRAP.md` в Project Sources. Это небольшой launcher; весь репозиторий в Sources добавлять не нужно.
4. Подключите GitHub к ChatGPT и разрешите приложению ChatGPT/OpenAI чтение и запись этого репозитория.

Настройка установленных GitHub Apps:
https://github.com/settings/installations/

Откройте нужную установку → **Configure** → **Repository access** и добавьте репозиторий кампании либо разрешите доступ ко всем нужным репозиториям.

Не передавайте в чат GitHub password, Personal Access Token или SSH private key.

## Как устроено хранение

```text
ChatGPT Project Instructions
          |
          v
00_DND_BOOTSTRAP.md          (стабильный Project Source launcher)
          |
          v
GitHub: main                 (engine/framework + пустой CAMPAIGN skeleton)
          |
          +--- campaign/game-A   (конкретный мир A)
          +--- campaign/game-B   (конкретный мир B)
          +--- campaign/shared   (общий multiplayer-мир)
```

`main` содержит CORE, RULES routing, SCHEMA, пустую структуру `CAMPAIGN/`, документацию и тесты. Он не содержит персонажей или фактов конкретной игры.

Каждая реальная игра живёт в своей долгоживущей `campaign/<name>` ветке и никогда не мержится обратно в `main` или в другую кампанию.

## Что происходит при команде «играть»

Если campaign-ветка явно не выбрана, мастер просматривает `campaign/*`, читает только `CAMPAIGN/MANIFEST.yaml` каждой игры и показывает краткий список: продолжить одну из них или начать новую.

Новая ветка создаётся от стабильного engine release/tag и уже содержит полный пустой `CAMPAIGN/` skeleton. Мастер заполняет manifest/config, создаёт player/PC и только минимальный стартовый участок мира.

## Lazy loading

Мастер не читает весь мир и историю. Примеры:
- NPC → компактный NPC index → одна запись NPC;
- локация → location index → одна запись локации и только релевантные сущности;
- старое событие → event index → ограниченный участок LOG;
- бой → только runtime + combat/adjudication/randomness;
- магия → только runtime + magic и точная механика нужного spell/feature.

Ссылка одной сущности на другую не означает автоматической рекурсивной загрузки.

## Сохранение без мусорных коммитов

Git commit не создаётся после каждого хода, броска или реплики. Изменения накапливаются и публикуются пакетами на естественных границах: конец сцены/боя, значимое перемещение, пауза/конец сессии, существенный набор durable changes, явное сохранение или maintenance.

В multiplayer изменения общих race-sensitive объектов (например уникальный предмет, общий NPC, дверь, локация или глобальный процесс) публикуются сразу после логического завершения, чтобы соседние сессии видели актуальный мир.

Если другой чат успел изменить ветку, Git не даёт молча затереть новый HEAD. Мастер сравнивает изменения: независимые объединяет, логически конфликтующие действия переоценивает по уже изменившемуся миру.

## Singleplayer и multiplayer

По умолчанию campaign работает в `singleplayer`: AI DM считается единственным писателем, а новый чат синхронизируется с HEAD ветки. По явной команде можно сделать resync.

`multiplayer` включается только явно. Игроки могут находиться в разных местах одного мира; состояние разделено на отдельные scene/entity records, чтобы независимые действия редко конфликтовали технически. Знания разных PC остаются раздельными даже при общей objective world truth.

## Правила D&D

Базовая rules version engine — D&D 2024 / SRD 5.2.1. Полный SRD не копируется в runtime-контекст. `RULES/` маршрутизирует запросы, а точные class/spell/item/monster mechanics загружаются адресно из уже сохранённых campaign records или официального источника.

## Обновление engine

Общие улучшения идут в `main`. В живую campaign-ветку их по умолчанию интегрируют merge. Rebase допустим только явно для остановленной неконкурентной ветки, после чего требуется полный resync cached SHA. Несовместимые schema changes оформляются через `MIGRATIONS/`.

## Статус

До первого стабильного engine release репозиторий считается pre-release. Экспериментальная сцена с таверной и черновик мага из установочного чата не являются игровым каноном.
