# Hedgelion D&D Master

AI Dungeon Master engine для длительных D&D-кампаний в ChatGPT Projects с GitHub как постоянным хранилищем канона.

Цель проекта — чтобы кампания оставалась последовательной через десятки и сотни сессий, а рабочий контекст зависел от сложности текущей сцены, а не от возраста мира.

## Что умеет мастер

- ведёт D&D 2024 с механической базой SRD 5.2.1;
- использует отдельный слой GM craft: подготовка ситуаций вместо railroad-сюжета, robust clues, living NPC/factions, strong starts, pacing, lore и campaign operations;
- применяет обязательную AI reasoning discipline против типичных LLM-ошибок: sycophancy, фальшивые выборы, ретконы, NPC-omniscience, скрытая подгонка бросков, удобные сущности «по запросу игрока» и расползание контекста;
- хранит канон структурированно в GitHub, а не в ChatGPT Memory, File Library или длинной истории чатов;
- подгружает NPC, локации, события и правила адресно через lazy loading;
- автоматически ведёт состояние, инвентарь, NPC, отношения, активные процессы, журнал и checkpoints;
- поддерживает независимые кампании через ветки `campaign/*`;
- поддерживает `singleplayer` и явный shared-world `multiplayer`, где действия разных игроков могут менять один общий мир.

## Архитектура

```text
ChatGPT Project
  Project Instructions
          |
          v
  00_DND_BOOTSTRAP.md      <- Project Source launcher
          |
          v
GitHub repository
  main                     <- engine + пустой CAMPAIGN skeleton
   |
   +-- campaign/game-a     <- отдельная игра
   +-- campaign/game-b     <- отдельная игра
   +-- campaign/shared     <- общий multiplayer-мир
```

`main` не содержит персонажей, мира или событий конкретной игры. Он содержит только универсальный engine и полностью пустую структуру кампании.

Новая игра создаётся отдельной веткой от стабильного engine release. Игровые ветки не мержатся обратно в `main` и не мержатся друг в друга.

## Изоляция памяти

При создании ChatGPT Project рекомендуется режим **Project-only memory / «Память только в проекте»**. Он изолирует проект от сохранённых воспоминаний и чатов за его пределами.

При этом чаты внутри одного Project всё ещё могут использовать друг друга как контекст, поэтому Project memory не является источником канона. Истина кампании хранится только в соответствующей GitHub branch.

Для максимально строгой изоляции разных кампаний рекомендуется отдельный ChatGPT Project на каждую campaign-ветку или shared-world кампанию. Один repository при этом может содержать сколько угодно независимых `campaign/*` веток.

File Library для Project-only проектов может быть недоступна; Hedgelion от неё не зависит. Bootstrap загружается непосредственно в Project Sources, а постоянное чтение/запись выполняется через GitHub app.

## Основные каталоги

- `CORE/` — AI reasoning, GM craft и runtime-модули мастера.
- `RULES/` — маршрутизация точных механик D&D.
- `SCHEMA/` — форматы persistent state и сущностей.
- `CAMPAIGN/` — полностью пустой каркас новой кампании; в игровых ветках наполняется каноном.
- `ARCHITECTURE/` — устройство веток, хранения и синхронизации.
- `TESTS/` — regression/audit сценарии для поведения мастера.
- `RELEASE/` — release checklist и служебный аудит.
- `INSTALL/` — всё необходимое для подключения engine к ChatGPT Project.

## Установка

Полная инструкция находится в **`INSTALL/README.md`**.

Для установки используются только два файла:

- `INSTALL/PROJECT_INSTRUCTIONS.txt` — текст для поля Project Instructions;
- `INSTALL/00_DND_BOOTSTRAP.md` — launcher, который нужно добавить в Project Sources.

Весь репозиторий добавлять в Project Sources не нужно.

## Как работает контекст

Во время игры всегда загружаются только `CORE/RUNTIME.md` и `CORE/AI_REASONING.md`. Остальные модули подключаются по ситуации. Игровые данные ищутся через компактные индексы и stable IDs.

Например, упоминание NPC не означает загрузку всего мира: мастер читает NPC index, затем одну нужную запись и только те связи, которые необходимы для текущего решения.

## Сохранение

Мастер не создаёт Git commit после каждого броска или реплики. Durable changes сохраняются осмысленными пакетами на естественных границах сцены/сессии. Git защищает branch HEAD от stale writes; при multiplayer-конфликте мастер сравнивает изменившийся мир и переоценивает логически несовместимое действие, а не перетирает канон.

## Статус

Engine `0.1.0` готовится как первая чистая стабильная база до создания production campaign branch.
