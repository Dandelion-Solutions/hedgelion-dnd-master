# D&D Master by Hedgelion

Этот репозиторий содержит D&D Master — систему для долгих одно- и многопользовательских D&D-кампаний с AI-мастером.

Главная идея: игровой мир живёт дольше отдельного чата. Персонажи, отношения, предметы, тайны, последствия и история сохраняются в GitHub и остаются консистентными через новые разговоры и десятки сессий.

Можно играть одному, вести несколько независимых приключений и переключаться между ними, либо открыть конкретную кампанию друзьям. В общем мире игроки могут находиться в разных местах и действовать независимо; изменения одного становятся частью мира для остальных.

Создатель кампании контролирует её режим. В `singleplayer` только он может играть и сохранять изменения; остальные могут наблюдать. В `multiplayer` явно связанные игроки получают возможность влиять на общий мир, но переключать режим кампании по-прежнему может только её создатель.

Мастер ведёт D&D 2024 / SRD 5.2.1, самостоятельно отслеживает состояние мира и использует отдельные AI-reasoning и GM-craft правила против фальшивого выбора, ретконов, NPC-всеведения, подгонки бросков и расползания контекста.

Подробная установка: [`INSTALL/README.md`](INSTALL/README.md).

## Подробности для нёрдов

*Я предупредила :)*

Игровые ветки имеют нейтральные технические ID:

```text
main
├── campaign/20260813
├── campaign/20260814
└── campaign/20260814-02
```

Формат — `campaign/YYYYMMDD`; при нескольких новых кампаниях в день добавляется `-02`, `-03` и т. д. Название мира, режим, автор и число игроков в branch name не кодируются.

`main` содержит engine и полный пустой `CAMPAIGN/` skeleton. Конкретный канон существует только в `campaign/*`; игровые ветки не мержатся обратно в `main` и друг в друга.

Основные каталоги:
- `CORE/` — runtime, AI reasoning, GM craft и специализированные модули;
- `RULES/` — маршрутизация механик D&D;
- `SCHEMA/` — форматы persistent state;
- `CAMPAIGN/` — пустой каркас новой игры;
- `ARCHITECTURE/` — ветки, storage, sync и ownership;
- `TESTS/` — regression checks;
- `INSTALL/` — подключение к ChatGPT Project.

Канон хранится только в GitHub campaign branch. ChatGPT Memory, File Library и старые чаты не являются базой данных. Project-only memory рекомендуется как дополнительная изоляция, но один ChatGPT Project может обслуживать несколько кампаний.

Owner не дублируется в `MANIFEST`: он определяется по `author.login` первого campaign-specific initialization commit. Этот login сравнивается с текущим GitHub user для owner-only операций; в `singleplayer` тот же check обязателен для всех gameplay writes.

Git commits создаются пакетами на естественных границах, а не после каждого броска. В multiplayer stale HEAD приводит к semantic resync: независимые изменения объединяются, логически несовместимые действия переоцениваются по уже изменившемуся канону.
