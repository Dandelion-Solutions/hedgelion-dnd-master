# Схемы данных кампании

Каталог `SCHEMA/` описывает стабильные форматы persistent state. YAML-файлы кампании должны соответствовать этим логическим схемам; поля могут расширяться совместимым образом, но существующее значение поля нельзя менять на другое значение/смысл без повышения `schema_version` и миграции.

## Общие принципы

- Все значимые сущности имеют стабильный уникальный `id`.
- Ссылки между сущностями хранятся по ID, а не копированием полных записей.
- `null` означает «значение отсутствует/не задано»; неизвестный факт нельзя заменять правдоподобной догадкой.
- Отсутствие поля означает, что поле неприменимо или ещё не материализовано; это не должно автоматически интерпретироваться как `false`.
- Для игровых дат используется структурированное внутриигровое время, заданное конкретной кампанией. Реальное время Git используется только для технического аудита.
- Массивы знаний/связей не должны разрастаться бесконтрольно: исторические детали выносятся в `LOG`, а сущность хранит актуальное состояние и релевантные ссылки.
- Секретная объективная информация хранится отдельно от информации, известной PC/игроку.

## Версионирование

`schema_version` относится к формату persistent campaign data.

Совместимые добавления полей могут сохранять версию. Изменение семантики, типа обязательного поля или структуры, требующее переписывания существующих кампаний, повышает версию и требует записи в `MIGRATIONS/`.

`engine_version` и `schema_version` независимы: Framework может получить новую версию без изменения формата данных.

## Основные типы

- `campaign_manifest.schema.yaml` — идентичность кампании и режим синхронизации.
- `current_state.schema.yaml` — минимальное горячее состояние мира/активных сцен.
- `pc.schema.yaml` — персонаж игрока и механическое состояние.
- `npc.schema.yaml` — значимый NPC.
- `location.schema.yaml` — локация и постоянная геометрия/состояние.
- `faction.schema.yaml` — фракция/организация.
- `item.schema.yaml` — значимый предмет.
- `lore.schema.yaml` — объективный устойчивый факт мира.
- `secret.schema.yaml` — скрытая объективная истина/процесс.
- `thread.schema.yaml` — активный процесс, угроза, проект или задача.
- `event.schema.yaml` — семантический append-only факт перехода состояния.
- `checkpoint.schema.yaml` — recovery boundary.
- `index.schema.yaml` — компактный индекс сущностей.

В runtime загружается не каталог схем целиком. Схема нужна при создании/миграции/валидации соответствующего типа записи или при сомнении в формате.
