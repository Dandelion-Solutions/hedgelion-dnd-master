## 1. Mandate

WP-09 is the R2.7 audit domain for the accepted Context Runtime's bounded
discovery, retrieval, packet allocation and resource behaviour. It determines
whether current repository surfaces can realize this existing law without
turning indexes, caches, full CORE presence, current chat, SQLite or a
convenience scan into a new source of authority.

The authoritative R2.7 scope-discovery owner fixes the mandatory questions:

1. Can current records/indexes support bounded discovery before full load for
   every relevant domain?
2. Are required packet floors, optional degradation and `UNSATISFIABLE`
   representable without exact hidden token telemetry?
3. Are there hidden campaign-wide scans in normal hot paths?
4. Are scene/location/current indexes sufficient as routing hints without
   becoming closed-world authority?
5. Are context/resource assumptions compatible with the supported ChatGPT
   profile?

This is an architecture-to-machine and machine-to-architecture conformance
audit. It does not authorize implementation, new retrieval topology, a provider
API, a vector database, a generic graph, an extra prompt/cache, a background
worker, persistent fairness state or a storage migration.

## 3. Accepted constraints that WP-09 preserves

- R2.3 Context Runtime is a bounded ephemeral logical projection over current
  native owners and admitted evidence. Discovery precedes full load; required
  closure is typed, finite and profile-bound.
- Discovery/index metadata are routing-only. A discovered candidate still
  requires routed currentness and eligibility before role-local semantic use;
  an omitted index entry is not closed-world proof.
- Required packet members are allocated first at their legal representation
  floors. Optional ranking cannot evict required evidence, and pressure cannot
  silently downgrade an exact/minimum requirement below contract.
- The only assembly outcomes are `ASSEMBLED`, `ASSEMBLED_DEGRADED` and
  terminal `UNSATISFIABLE`. A caller selects a registered finite alternative;
  it does not loop, guess or invent a new profile.
- R2.4 requires phase rebind and minimal typed transport. R2.1's broad
  continuity/history orientation may trigger only dependency-specific bounded
  escalation to a stronger current/exact owner.
- Full shipped CORE cache, semantic module activation and campaign data retrieval
  are distinct. `PLAY_POLICY.md` requires complete CORE preload once but
  explicitly keeps campaign/world/entity retrieval lazy and decision-scoped.
- R2.6 prohibits dependence on exact hidden context/token telemetry. One central
  conservative estimator, R2.3 floors, legal degradation and finite fallback are
  the accepted host-profile direction.
- SQLite/HOT may physically host owner-state working copies or derived
  indexes/caches under their existing contracts, but format/freshness does not
  create semantic authority or a persistent `RoleContextBundle`.
- Story, current chat, indexes, caches and preparation can orient/retrieve only
  within their owner contracts; none outranks a current routed native source.

## 6. Required Step-2 proof and exit criteria

For every material context-loading surface, record:

```text
source/item and authority class
consumer/purpose/profile and required versus optional evidence
discovery channel, finite expansion and full-load boundary
currentness and eligibility route
legal representation floor / optional ranking / budget-estimator responsibility
ASSEMBLED | ASSEMBLED_DEGRADED | UNSATISFIABLE disposition and caller path
ephemeral / derived / operational / durable / explicit NO-REPRESENTATION result
architecture -> machine mapping
machine -> architecture owner or stale/debt/implementation-only classification
test/evaluation/maintenance route
cross-domain forward obligation, safe-defer trigger or no-delta rationale
```

The evidence must establish, without sampling shortcuts:

- which current record/index/template family provides a legal compact discovery
  hint and which authority resolves the full/current record;
- whether ordinary hot paths perform only decision-level targeted retrieval;
- whether every required packet has a legal minimum representation and whether
  optional material can be reduced without semantic loss;
- whether the central estimator and finite fallback preserve R2.6's no-hidden-
  telemetry guarantee;
- whether traces/indexes/HOT/SQLite are protected derived/operational support
  rather than semantic authority;
- which current tests cover cache/activation/lazy retrieval and what behavioural
  verification remains for future implementation;
- every material gap/conflict/debt with an exact operational disposition.

Step 2 may create evidence slices under `research/` only when the actual
dependency graph requires them. It must not create a canonical specification
merely by copying audit evidence.

## 7. Failure probes for the critic and later audit

At minimum challenge:

- full CORE preload is misread as permission to preload or semantically use all
  campaign data;
- a scene/location/index omission is treated as proof that no relevant record
  exists;
- a derived index, current-chat material, Story, SQLite cache or trace defeats
  routed currentness/eligibility;
- optional content evicts a required representation floor;
- `UNSATISFIABLE` loops, guesses or silently drops a required dependency;
- a local token/character heuristic bypasses the central estimator;
- history retrieval falls back to whole LOG/campaign scanning;
- a S6D `MechanicalContext`, session/checkpoint or generic schema is promoted
  into R2.3 role-context authority;
- a performance shortcut changes authority, disclosure, mechanics, recovery or
  player agency;
- WP-09 silently decides WP-10/11/12/18/24/25 physical mappings.
