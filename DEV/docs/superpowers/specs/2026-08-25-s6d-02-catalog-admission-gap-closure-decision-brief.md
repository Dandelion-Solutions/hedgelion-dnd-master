# S6D-02 — Catalog Admission and Gap Closure — Decision Brief

Status: **STEP 3 COMPLETE — NO HUMAN DECISION REQUIRED**

## Established facts

- Catalog 2.0 has 67 registry families / 571 IDs.
- Exact accounting yields 192 S6D-primary, 276 engine-enum consistency and 103 inherited Round-2 IDs.
- Admission and realization are different claims.
- Current machine vocabulary contains no newly proven stale registered ID.
- Four active prose/consumer surfaces contain stale or ambiguous ownership wording.
- S6D-01 requires one actual logical ruleset package admission boundary; physical seed/manifest verification remains downstream.
- Existing owners already settle the class model, execution authority, accepted-work retention and Round-2 ownership.

## Decision

Adopt an evidence-backed admission system with:

1. exact per-ID ledger-to-catalog set equality;
2. family profiles plus per-ID overrides;
3. admission dispositions separate from realization state;
4. full S6D admission only for S6D-primary IDs;
5. inherited consistency treatment for engine enums and Round-2 vocabulary;
6. exact downstream S6D/R2.x/WP routing;
7. one nonselectable pre-release built-in package profile;
8. coordinated stale wording cleanup;
9. no current `core-catalog.json` ID removal.

## Alternatives rejected

- undocumented family-level admission: insufficient item-level proof;
- preserve/defer: launders placeholders and stale references;
- direct-flow-only catalog: breaks valid indirect owners and reopens accepted class architecture.

## Material effects

- S6D-03–09 receive exact lists of active obligations rather than an ambiguous registry.
- S6D-11 receives a logical package profile, ledger schema and finite failure mapping to materialize/test.
- R2.1–R2.6 and paused WP-07+ remain closed/not pulled forward.
- No runtime behavior or released-campaign migration changes.

Human decision required: **NO**.
