# HDM Role-Context Validation Protocol 1 — Sequential Containment

Status: **COMPLETED VALIDATION EVIDENCE — NON-CANONICAL ARCHITECTURE INPUT**

Date: 2026-08-23

## Purpose

This completed validation tested whether HDM logical roles can be activated sequentially inside one persistent conversational history while preserving useful role-local information discipline.

The question was behavioral rather than physical:

> When information remains physically present in shared history, does the active logical role nevertheless act only from its allowed role context?

The validation does not claim that ineligible information was absent from model cognition. It measures whether that information materially influenced observable role behavior.

## Setup

The run exercised multiple logical role activations across one long shared history.

Key properties:

- 160 scored Subject probes;
- 227 submitted Subject responses;
- naturalistic semantic probes separated active-role evidence from physically present but role-ineligible information;
- positive controls made the same kind of information lawfully eligible later;
- a separate lexical/opaque-choice channel attempted to detect priming effects.

The validation was designed as an early feasibility and instrument check rather than as a production game-quality benchmark.

## Primary result

The strongest channel was the naturalistic semantic channel:

- **64/64 PASS**.

Across those probes, the active logical role consistently behaved from its supplied knowledge/frame rather than indiscriminately using information that was merely present elsewhere in shared history.

This result materially weakens the assumption that every HDM logical role requires a separate persistent conversation or dedicated physical agent merely to preserve useful behavioral separation.

## Hidden-to-eligible transition behavior

The run also demonstrated the important distinction between containment and permanent ignorance.

When information remained role-ineligible, the active role did not visibly rely on it. When the same kind of information later became lawfully available through the role frame or visible evidence, the role was able to use it normally.

This supports the intended HDM distinction:

```text
physical availability != role eligibility
role eligibility change -> behavior may change
```

## Lexical/opaque-choice limitation

The lexical anti-priming channel was not treated as primary evidence.

The Subject appeared capable of recognizing conspicuous experimental structure and avoiding suspiciously familiar options. Therefore an unusually low target-hit rate in that channel cannot be interpreted as proof of memory absence or strict isolation.

Durable lesson:

- naturalistic semantic behavior is stronger evidence than recognisable canary/anti-priming choice structure;
- a model can react to the fact that it is being tested;
- future containment evaluation should prefer balanced semantic alternatives, lawful positive controls and ordinary role behavior.

## Provenance limitation

The run had a manual prompt-provenance weakness. Exact transmitted prompt text could not always be reconstructed with sufficient certainty after operator handling.

Therefore this protocol is classified as:

> **strong pilot / instrument-validation evidence, not pristine confirmatory evidence**.

The result is still useful because the naturalistic channel was large, coherent and directionally consistent, but later validations were required before changing architecture.

## Engineering inference

This validation supports the following inference:

> Sequential HDM logical roles can preserve useful behavioral containment inside one persistent physical conversation when role-local framing is explicit.

It does **not** establish:

- physical context isolation;
- cognitive absence of ineligible material;
- safe execution of several incompatible logical roles inside one single generation;
- production suitability across all reasoning configurations;
- long-campaign gameplay quality.

Those stronger questions were left to subsequent validation protocols.

## Step-6 relevance

Protocol 1 should be read as the first evidence layer for Step 6 physical orchestration design.

It establishes that "one logical role = one persistent physical conversation" is not empirically necessary for the tested behavior.

It does not by itself authorize collapsed same-generation execution. That stronger topology is evaluated by Protocol 2.
