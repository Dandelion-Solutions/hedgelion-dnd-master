# HDM Runtime Source and Provenance Boundary

load_when: explicit rules-source/provenance/audit request or bounded preparation source audit

This runtime file defines where current HDM semantics, rules-source routing, legal attribution and technical artifact provenance are obtained. It is not a development-research bibliography and does not preserve which external materials were consulted while HDM was designed.

## Current HDM semantics

Gameplay and Master behavior are defined by the current HDM `CORE/`, `RULES/`, schemas and campaign/runtime contracts. Their independently stated HDM rules control execution. Historical development-source narratives are not runtime authority.

General GM-craft guidance needed during play is local runtime knowledge in the applicable CORE owners. The runtime does not need to browse development sources to reconstruct those principles.

## Rules-source routing

When an exact rules-source lookup is actually required, use the current runtime rules-source owner:

- `RULES/OFFICIAL_SOURCES.md`.

That file is operational rules routing. It is not a record of development inspiration or research history.

## Legal and approved attribution

Required license/legal attribution and any explicitly approved attribution are owned by the runtime legal payload, including as applicable:

- `LICENSE`;
- `NOTICE`;
- `THIRD_PARTY_NOTICES.md`;
- `LICENSES/`.

These materials must not be removed by research-provenance sanitation.

## HDM technical artifact provenance

Technical provenance required to identify or validate HDM artifacts is also retained. Depending on the owning contract, this includes:

- `ENGINE_VERSION.yaml` semantic release identity;
- generated `RUNTIME_PACKAGE.yaml` exact built-package provenance;
- final runtime ZIP digest/checksum evidence;
- exact source/commit or release/tag identity when required;
- version/generation and ruleset-set identity;
- update/migration lineage;
- deterministic publication/currentness evidence.

Technical artifact provenance is distinct from development/research-source provenance.

## Public boundary

Current public `DEV/` and `GAME/` material states HDM semantics in HDM terms. Source-specific development/research history is not retained merely for attribution of ideas or design inspiration. Git history remains repository history; no history rewrite is required.
